# Mid-360 闭环修复与对照实验

本次目标是修复 SEU library 原包在线轨迹首尾约32m不闭合；原始首尾扫描的独立配准估计约0.16～0.17m，详见 seu-endpoint-check.md。所有下述完整实验使用同一ROS2转换包，保留原始消息、点内时间和录制时序，rate=1、delay=2秒。未裁去运动起步，也未插入静止数据。


## 最终结果与统计口径

**此包的最终优化轨迹已闭合，首尾0.16104m。** 原始首尾点云独立配准约0.16～0.17m，因此不支持“数据集本身首尾相距32m”的解释。没有外部真值，不能将0.161m称为ATE或定位误差。

| 测量对象 | 3D首尾距离 |
|---|---:|
| 原配置在线后端消息序列 | 32.083m |
| 最终配置在线前端消息序列 | 6.027m |
| 最终配置在线后端消息序列 | 6.029m |
| 最终配置保存的优化关键帧轨迹 | **0.16104m** |

最后一条在线消息仍是闭环前估计：bag的最后IMU为1777273441.889098496，在线后端到此停止更新；末段异步配准在播放结束之后才提交全局因子。后端高频定位发布由新里程计输入驱动，已发布的历史消息不会被追溯修改。没有添加虚构IMU或重复时间戳来“刷新”数值。因此在线消息首尾与最终优化轨迹首尾必须分开报告；本次修复的是图中的真实闭环，**没有声称最后一条在线消息也已变为0.161m**。真实连续运行中，后续里程计输入使用更新后的图投影；本包结束后的在线刷新未单独回放验证。

日志证据：末帧762对0～5共6个候选通过几何验证，形成6/6一致团，择优仅提交762→5一个因子（关键帧跨度757），NIS=15.3288/6，p=0.0178481 > 0.001；修正6.03393m、4.25716°。保存763个优化关键帧，起止stamp=1777273013.200408 / 1777273441.7008543，端点差 `[0.006429, 0.116893, -0.110585] m`。这是真实跨整圈约束，不是之前的局部回环数量。

最终整包：观察器收到85965条IMU，前端78271条定位、后端78214条定位、4144组配对点云，4150条状态均为NORMAL，三个进程退出码均0，观察器无错误、无停链。前后端时间戳间隔最大约334ms，这不是硬实时保证。整体输入链路仍保留一次早先TimeFault未定位的限制，不能宣布所有稳定性问题均已解决。

证据文件：[汇总JSON](mid360-fixed-results.json)、[关键帧轨迹](mid360-fixed-keyframes.txt)、[关键日志](mid360-fixed-evidence.log)、[继承展开配置](mid360-fixed-backend-merged.yaml)、[测试统计](mid360-fix-tests.json)。配置归一化后的值由启动日志核实为history=0、clique=3、kernel=huber。

## 修改

1. 新增 `config/mapping_mid360.yaml` 专用前端配置，使用已有松耦合ESKF的几何自适应激光观测协方差。原固定 `0.01*I` 同时用于m²与rad²，旋转标准差约5.73°，在充分约束的场景中仍显著削弱激光姿态纠正。新配置使用5cm平面残差尺度（variance=0.0025m²）、10倍相关性膨胀、归一化方差下限1e-6，弱方向仍增大方差，不改变匹配/创新门限。这是实验验证的配置，不是厂家标定或所有场景通用的噪声模型。
2. Mid360导航输出体素从0.01m改为0.1m，避免本次室外范围的PCL体素索引溢出警告；该处理在后端完整点云回调之后，不改变匹配/后端输入点集。用户原mapping_m.yaml未覆盖。
3. 后端 `LoopMatcher::verifyCandidate` 增加可选的重访初值：原里程计初值验证失败、候选有描述子yaw、相隔至少60关键帧、预测平移超过1m时，在目标关键帧原点附近重新启动配准。它只是一种几何假设，不是把输出位置强制设为原点；结果仍需通过几何、重叠率、候选PCM与图NIS验收。
4. 新重访策略为历史锚点补充有界的后续历史扫描，避免第0关键帧永远只有一帧稀疏目标；排除当前源窗口的所有帧，默认关闭时保留原行为。
5. `config/tdt_backend_mid360.yaml` 开启该策略，并将候选空间预筛半径从7m扩大到40m。这个半径仅用于召回候选；几何平移/角度、重叠率、NIS验收不放宽。另单独处理了不适用的世界Z先验和历史PCM固定容差（见下文）。保持后端全局开关默认关闭，现有其他配置行为不变。
6. 此前 `validation.max_z=0.5` 并非“配准后的两扫描高度差”，而是世界Z方向的里程计与闭环测量残差。本前端的初始世界Z不保证重力竖直，真实首尾约束因此被约2.15m的Z残差拒绝。仅在Mid360专用配置中设为0，改由未修改的完整6维图NIS判断创新；不是取消点云几何验证，也不是修复了前端重力坐标系。
7. Mid360专用配置将图鲁棒核从Cauchy(size=0.5)改为Huber(size=1)。已经通过NIS的大闭环仍可能被Cauchy递减权重压到几乎不起作用；Huber保持有界影响，同时允许已验收的真实闭环推动图收敛。不是直接移动终点或绕过图优化。
8. 实际在线图还存在历史PCM否决：它将已接受的局部回环通过原始里程计链接到当前全局重访，跨越数百秒仍使用固定1m平移容差。这与允许纠正数米累计漂移不相容。专用配置将 `pcm.min_consistent_loops` 设为0，同时将当前批次 `min_candidate_clique_size` 从1提高到3，保留候选PCM的1m/15°容差与完整图NIS。当前一致团共享源点云，**不是三份独立测量**，仍只提交其中最佳一个因子，避免重复计数信息。这是针对本配置的验收策略调整，不声称历史PCM未改变。
9. 修复配置归一化与验证器语义不一致：验证器支持 `min_consistent_loops=0`，归一化此前却强制最小1。现在保留显式0，负数恢复默认1。启动日志新增归一化后的history/clique/kernel，避免仅凭YAML推断运行值。
10. 回放工具保存前后端配置快照；汇总增加起止stamp、时长、IMU总数、端点XYZ差和接受的回环关键帧对。修复观察器Ctrl-C时重复shutdown导致证据未写盘的问题，中断回放明确标记为不完整。

## 从在线保存地图定位闭环失败

使用 `replay-mid360-neighborhood-full` 保存的764帧地图，检查末帧763对起点0，实际描述子yaw=0.558505rad、距离0.328241：

| 配准初值与目标地图 | 收敛 | 对应比例 | RMSE | 几何验收 |
|---|---|---:|---:|---|
| 里程计初值、单帧目标 | 否 | 0.1333 | 0.4107m | 否 |
| 重访初值、单帧目标 | 是 | 0.3100 | 0.2099m | 否 |
| 里程计初值、17帧历史邻域 | 否 | 0.3678 | 0.4240m | 否 |
| 重访初值、17帧历史邻域 | 是 | 0.6793 | 0.1486m | 是 |

最后一项配准平移 `[0.01619, 0.11814, -0.10989] m`，长度约0.162m，与原始点云独立首尾检查相符。但原世界Z门限仍拒绝这条约束。禁用这个不适用的轴向先验后，它通过几何验证。

离线按保存位姿重建里程计链，以同一测量分别比较鲁棒核：两者NIS=14.3059、p=0.0263997，均通过0.001概率门限；Cauchy优化后首尾5.0844m，Huber为0.162083m。该诊断使用保存的优化位姿重建链，没有历史局部回环因子，**不是原在线图的精确复现**；最终效果以完整在线回放为准。工具位于独立后端仓库 `src/backend/test/tools/inspect_loop.cpp`，显式构建目标 `backend_loop_inspect`，不安装、不进入运行节点。

`replay-mid360-huber-historical-pcm-full` 完整在线输出仍为5.992m，仅13条局部回环，无起点重访。相同保存地图末帧762对起点0离线几何验证通过，对应比例0.6803、RMSE 0.1499m。在线与离线差异在于历史局部回环参与的PCM前置验收；代码此前在该分支静默返回，现补充诊断日志。

保留的中间失败实验包括 `replay-mid360-place-seed-radius40-full`（尚无历史邻域支持）、`replay-mid360-neighborhood-full`（仍启用世界Z门限）。`replay-mid360-world-frame-cauchy-partial` 在发现鲁棒核问题后主动中断，metrics标记incomplete，不能当作完整验证。

另保留 `replay-mid360-huber-input-fault`：首次Huber在线回放约20秒触发前端TimeFault(reason=8)，随后人工停止，观察器收取9112条IMU，未发现其接收序列有>50ms或非递增时间间隔，但前端订阅所见序列没有逐条录制，因此具体传输/调度原因尚未证实。不能据此宣称输入链路长期稳定，也不能将该轮算作完整通过。IMU故障保护未关闭。

还保留 `replay-mid360-clique-clamped-full`：YAML请求历史支持0，但旧归一化强制为1，实际日志明确记录末帧759对0/1/2/3/4被historical PCM否决，故不是新策略的有效验证。该轮前端初始化延迟（加计方差超阈），首条定位比上一轮晚约1.4秒，后端首尾4.807m不能简单解释为PCM改进。保存地图首尾4.764m。配置继承展开快照不等于C++归一化后有效配置，后续以启动日志和配置解析单测核实。

## 测试

五组前端CTest通过；后端六组共80个用例通过（原77+新增3）。新增用例覆盖：20m里程计偏差时找回真实几何重访、几何平移门限仍有效、无yaw/近期候选不使用该初值，以及几何找回后仍必须通过联合NIS检查才能修改轨迹。第三个新增用例经过实际配置解析验证显式0历史支持要求不会被改回1，同时当前候选PCM仍拒绝不一致测量、负值仍恢复默认保护。第一次CTest启动漏source ROS导致ament_cmake_test导入失败；修正启动环境后全部通过，没有跳过用例。

## 运行入口

在已构建、source的ROS2环境中：

```bash
ros2 launch adaptive_lio tdt_backend.launch.py \
  frontend_config:=/workspace/Adaptive-LIO/src/Adaptive-LIO/config/mapping_mid360.yaml \
  backend_config:=/workspace/Adaptive-LIO/src/Adaptive-LIO/config/tdt_backend_mid360.yaml \
  use_sim_time:=true
```

原始Livox点云外参、g单位假设与此前报告相同，实车必须匹配实际驱动输出。前端仍是松耦合，未引入ZLIO。后端修改位于独立z-localization仓库，同时已归档为 [可应用补丁](../../tools/patches/README.md)，需重建backend，不能只复制YAML给旧二进制。

初始化仍使用原逻辑；此次实验并未证明运动静止误判已修复。初始世界Z不保证重力竖直，导航固定世界Z裁剪也仍有语义限制。两者不能仅凭闭环改善就宣布解决。最终闭合距离采用保存的优化关键帧，在线历史消息另列，不是真值ATE/RPE；跨数据集鲁棒性需另行验证。


复算闭合指标（需要numpy）：
```bash
python tools/summarize_tdt_replay.py \
  /workspace/adaptive-lio-env/replay-mid360-fixed-full \
  --optimized-keyframes docs/validation/mid360-fixed-keyframes.txt
```
完整回放通过 `tools/replay_tdt.py`，使用上文两个专用配置、SEU转换包 `seu-library-ros2-fast`，rate=1；另启用backend `trajectory.save_on_shutdown=true` 保存优化关键帧。ROS及前后端安装空间必须先source。
